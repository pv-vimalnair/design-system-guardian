# Guardian v0.3.6 Machine Rule Enforcement Implementation Plan

## Goal

Implement the approved v0.3.6 specification as one additive public release,
without changing the immutable policy or regressing any v0.3.2-v0.3.5
contract. Work only in the isolated `codex/guardian-v0.3.6` branch.

## Checkpoint 0: Lock the inherited baseline

1. Record the v0.3.5 policy digest, public file inventory, version manifests,
   skill count, core test count, Flutter test count, and focused activation
   results.
2. Run the existing Python, Flutter contract, skill, packaging, and privacy
   suites with `PYTHONPATH` pinned to this plugin root.
3. Add an inheritance harness that executes the public v0.3.2-v0.3.5 test
   contracts in isolated temporary checkouts and converts worker/API mismatch
   into ordinary test failures.
4. Stop if the inherited baseline is not green for a reason introduced by the
   branch.

## Checkpoint 1: Evaluator-v2 authorization and rule inventory

1. Add strict schemas for the evaluator-v2 permission, append-only local
   authorization record, pointer, and `rules list` projection. Retain every
   existing schema unchanged and readable.
2. Add contained local paths for evaluator authorization history and pointer;
   reject links, redirects, partial state, divergent replay, and cross-profile
   evidence.
3. Implement `guardian-flutter-usage-rules-v2` preview/apply with exact binding
   to policy, profile, rule snapshot, v0.3.5 permission lineage, source cut,
   capability matrix, and evaluator-contract digest.
4. Add `guardian rules upgrade preview`, `guardian rules upgrade apply`, and
   zero-write `guardian rules list` CLI surfaces using established exit codes.
5. Test permission denial, race, mutation, replay, interruption, profile
   isolation, old-permission non-authority, source blockers, zero-write list,
   canonical ordering, and privacy-safe output.

## Checkpoint 2: Strict Flutter config v3

1. Keep config v1/v2 readers and exact meanings.
2. Add config v3 schema and compiler output bound to evaluator-v2 permission,
   contract digest, rule snapshot, source cut, package, toolchain, exact
   constructors, exact variants, and inactive coverage reasons.
3. Compile all six machine predicate shapes only when every required identity,
   variant, and code mapping is exact and approved.
4. Reject unknown fields, unsupported contracts, mapping ambiguity, incomplete
   source, and attempted caller substitution.
5. Extend the host-owned Flutter contract validator and parity tests.

## Checkpoint 3: Analyzer-resolved rule evaluation

1. Extend the adapter config model with typed compiled rules while preserving
   v1/v2 parsing.
2. Build a bounded construction graph from analyzer-resolved constructor
   elements and syntactic argument containment only.
3. Add resolved `widget_class` ownership for Widget and `State<T>` classes;
   never infer ownership from names or helper call graphs.
4. Implement deterministic evaluation for:
   `forbidden_identity_in_scope`, `max_instances_per_scope`,
   `forbidden_nesting`, `required_companion`, `allowed_parents`, and
   `variant_context`.
5. Emit stable violations and explicit incomplete/not-assessed coverage;
   preserve suppression diagnostics.
6. Add Dart tests for exact boundaries, aliases, similar names, separate
   classes/units, State ownership, helpers, closures, collection children,
   wrappers, roots, incomplete graphs, variants, and suppressions.

## Checkpoint 4: Usage Rules audit lane

1. Retain audit-result v1 reading and the inherited design-system projection.
2. Add an additive audit-result v2 schema with `usageRulesLane` and strict
   canonical validation.
3. Project evaluator/config/adapter evidence into allowed, conflict,
   not-assessed, unsupported, source-blocked, or invalid lane status.
4. Require the new lane and inherited projection to agree; disagreement is an
   integrity error.
5. Seal the lane through finalize, coverage, run manifest, readable report,
   and post-run self-check without saving source content.
6. Test truth tables, incomplete coverage, judgment-rule blockers,
   informative-rule non-gating behavior, tampering, and privacy.

## Checkpoint 5: Generic installer status and recovery UX

1. Add zero-write status mode to the generic Agent Skills installer.
2. Compare exact package, policy, launcher, binding, skill, and runtime marker
   evidence and return `current`, `update_required`, `reload_required`, or
   `invalid`.
3. Map Windows access-denied/sharing-violation promotion failures to
   `reload_required` plus reason code `host_restart_required` after verified
   rollback.
4. Keep atomic staging, verification, rollback, downgrade refusal, and intact
   prior-install checks unchanged.
5. Test zero-write behavior, locked-root recovery, exact retry guidance, and
   refusal to kill processes or overwrite in place.

## Checkpoint 6: Skills, evolution, and public metadata

1. Update both skills with the plain-language evaluator permission, rules
   inventory, v2 audit lane, and host reload flow; create no third skill.
2. Add privacy-safe synthetic Elo evidence for verified v0.3.6 capabilities;
   keep local score and run history outside Git.
3. Update current SemVer metadata, portable host manifests, README, changelog,
   installation/update docs, and release notes to v0.3.6 without rewriting
   historical version evidence.
4. Run Plugin Evolution Manager health/evolution validation and resolve only
   confirmed v0.3.6 findings.

## Checkpoint 7: Release validation and publication

1. Run targeted tests after each checkpoint, then the complete Python and Dart
   suites, schema validation, lint/format, policy digest, skill pressure,
   inheritance, package, privacy, secret, Git history, and diff checks.
2. Build the public package and verify exactly two skills and one canonical
   Guardian core.
3. Push the branch, open the release PR, and wait for Windows and Ubuntu CI.
4. Merge only when required checks are green; tag and publish `v0.3.6` from the
   exact verified merge commit.
5. Install or bind that public release for Codex, Claude Code, OpenClaw,
   terminal/generic Agent Skills, Qwen Code, and Kimi Code.
6. Read back every host. Report any watched root as `reload_required` rather
   than claiming success.
7. Confirm the public tree, artifact, tag, release, and history contain no
   company or user data.

## Completion evidence

Completion requires the public release URL and commit, exact test results,
immutable policy digest, privacy/history result, Plugin Evolution Manager
result, and a per-host installed/read-back table. Any unavailable host or failed
gate remains explicitly incomplete.
