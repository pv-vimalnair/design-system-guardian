# Guardian v0.3.3 Design and Implementation Plan

## Outcome

Release one portable Guardian plugin that lets a compatible agent start protected design-system work through a plain-language, permission-based setup; proves exact Figma bindings and component lineage; reports design-system and UX/accessibility results separately; and never grants production authority without protected host evidence.

The public surface remains exactly two skills: `build-with-design-system` and `audit-design-system`.

## Non-negotiable boundaries

- Keep `policy/policy-v1.json` and its expected digest byte-identical.
- Never infer approval from a discovered Figma library, matching name, matching value, or matching appearance.
- Keep company profiles, catalog snapshots, observations, reports, and product content local.
- Reuse the existing Figma connection; add no credential store, service, dependency, or second Figma plugin.
- Preserve the Flutter adapter and duplicate-working-file enforcement.
- A missing sealed Guardian manifest always means `not Guardian-approved`.
- Generic/local hosts may prove design-system and UX/accessibility lanes, but `productionReady` remains false without protected enforcement-authority evidence.
- The Usage Rules Lane is v0.3.4 and is out of scope.

## User journey

1. The agent runs an internal setup status check.
2. If trust is absent, Guardian shows one plain-language permission prompt naming the exact company profile, approved libraries, catalog-authority key, and local changes.
3. With permission, Guardian atomically installs a verified local onboarding bundle. The user never types Guardian commands or copies policy files.
4. Guardian refreshes and pins one complete snapshot for the task.
5. The Figma collector records exact bindings, styles, component keys, variants, overrides, duplicate-file lineage, source version, and coverage.
6. Build uses only allowed identities or exact missing sentinels.
7. A quick UX/accessibility checkpoint runs when each screen is completed.
8. Final audit reruns all screen checks plus complete-flow checks and emits a readable report and sealed manifest.

A completely unconfigured company still needs a design-system owner to produce the trusted local onboarding bundle. Guardian must never manufacture the company authority or approve discovered libraries automatically.

## Internal architecture

- `guardian_core/onboarding.py`: read-only status, bundle validation, idempotent atomic apply, friendly structured outcomes.
- `guardian_core/adapter_dispatch.py`: selects the pinned `flutter` or `figma` target without weakening either adapter.
- `guardian_core/figma_adapter.py` plus `adapters/figma/`: validates a host-collected Figma observation against exact snapshot identities.
- `guardian_core/ux_evaluator.py`: evaluates sealed screen and final-flow evidence; callers supply evidence, never their own pass result.
- Existing audit, finalization, reporting, self-check, duplicate lineage, reconciliation, and release machinery are extended rather than replaced.

## Figma evidence contract

- Bound variable alias resolves to an exact stable variable key, type, collection, and active mode.
- Text uses an exact approved text-style key or complete approved bindings, including mixed ranges.
- Components/icons are real instances with exact remote main-component keys, approved properties, and no unapproved overrides.
- Duplicate working files generate the existing exact `workingFileInstances` evidence automatically.
- Raw values and inferred variable matches are violations even when visually identical.
- Source/document changes between collection and finalization invalidate the observation.
- Missing, incomplete, unavailable, stale, and unsupported evidence remain distinct.

## UX/accessibility contract

- Screen checks: readable contrast, target sizing, labels/semantics, hierarchy, component states, and focus/reading order where evidence supports them.
- Final-flow checks: navigation, reachability, errors, recovery, and cross-screen state coverage.
- Unsupported or missing evidence is `not_assessed`; a proven gap is `conflict`.
- UX conflict never changes a clean design-system lane to conflict.
- Inaccessible approved assets are reported as design-system gaps; Guardian does not restyle or substitute them.
- Quick checkpoints cannot grant production readiness. Final evidence is bound to evaluator digest, pinned source cut, and exact target.

## Compatibility safeguards

- Clear or bind a new frame's default white fill immediately.
- Set auto-layout parentage before `FILL` sizing.
- Clone and reassign read-only fills/effects arrays.
- Load fonts before text mutation.
- Use asynchronous page/node APIs where required.
- Use `componentProperties` and `setProperties`; do not depend on deprecated `variantProperties`.
- Treat `defaultVariant.createInstance()` as valid only after verifying the runtime object type; report wrapper mismatches instead of banning it.

## Execution plan

1. Add failing contract tests for setup, Figma observations, adapter dispatch, UX lane separation, reporting, privacy, and host routing.
2. Implement guided onboarding by composing existing create-once policy, profile, snapshot, and pinning functions.
3. Implement the strict Figma observation schema, collector contract, validator, and automatic duplicate evidence.
4. Generalize audit/finalization dispatch from Flutter-only to pinned Flutter or Figma targets.
5. Implement screen and final-flow UX/accessibility evaluation and fix design/UX lane conflation.
6. Extend readable reports, graceful structured failures, post-run reason codes, and two existing skill workflows.
7. Add supported-host routing metadata/instructions and retain the universal no-manifest fallback.
8. Update version, changelog, README, installation/update docs, and additive synthetic benchmarks.
9. Run targeted tests, full Python/Flutter suites, schemas, validators, privacy gate, deterministic plugin audit, and diff/secret checks.
10. Commit, push, publish v0.3.3, reinstall from the personal marketplace, and verify both skills with fresh agents and accessible Figma evidence.

## Acceptance criteria

- One permission applies a valid onboarding bundle; no files change before permission or after invalid/ambiguous input.
- Approved bound Figma identities pass; matching raw values, clones, detached instances, substitutions, and unauthorized overrides fail.
- Original and approved duplicate working files resolve through exact lineage without manual per-node configuration.
- Screen checkpoints and final-flow audits report independently from design-system compliance and production authority.
- Every stop explains stage, reason, unchanged state, one next action, and remaining requirements.
- Existing v0.3.2 artifacts remain readable; all existing Flutter and privacy guarantees remain green.
- Public release contains no company rule, catalog, prompt, product content, path, credential, or runtime report.
