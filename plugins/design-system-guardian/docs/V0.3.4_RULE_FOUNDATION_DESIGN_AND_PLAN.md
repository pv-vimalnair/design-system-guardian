# Guardian v0.3.4 Rule Foundation Design and Plan

## Outcome

Release the first independently recoverable Usage Rules Lane checkpoint. Guardian
v0.3.4 can parse and validate explicit design-team usage rules from a canonical
team artifact or an explicit Figma-description marker input, then emit a
deterministic preview report. It does not migrate profiles or snapshots, change
audit outcomes, generate Flutter diagnostics, or activate enforcement.

The public surface remains exactly two skills: `build-with-design-system` and
`audit-design-system`.

## Non-negotiable boundaries

- Keep `policy/policy-v1.json` and its expected digest byte-identical.
- Never treat a validation preview as approval, enforcement evidence, or
  production authority.
- Never infer a rule from ordinary prose. Only explicit `[dsg-rule]` markers and
  strict rule objects are parsed.
- Keep company rules and validation inputs local. Public source contains only
  synthetic example-company fixtures.
- Add no credential, service, background process, Figma connection, visible
  skill, or runtime dependency.
- Do not modify profile, snapshot, run-manifest, build-plan, audit-result,
  Flutter-adapter, Figma-observation, migration, or trust-anchor contracts.
- Preserve every v0.3.3 behavior when the new command is not invoked.

## Rule contract

`schemas/rule.schema.json` defines one strict rule with
`additionalProperties: false`.

Every rule has:

- `schemaVersion: 1`
- a stable lowercase `ruleId`
- `class: machine | judgment | informative`
- `appliesTo` with an explicit system, category, or approved identity target
- exact local provenance

Machine rules carry one predicate from the fixed v1 vocabulary:

- `max_instances_per_scope`
- `forbidden_nesting`
- `required_companion`
- `allowed_parents`
- `variant_context`
- `forbidden_identity_in_scope`

v0.3.4 validates predicate structure only. It never claims that a predicate was
evaluated. Judgment and informative rules carry exact statements. Rule content
is data and never becomes an agent instruction.

## Accepted preview inputs

`guardian rules validate` requires an explicit format.

### Team artifact

`--format artifact` reads a UTF-8 JSON array of strict rule objects. Duplicate
JSON keys, unknown properties, duplicate rule IDs, invalid predicates, and
invalid provenance fail validation.

### Figma description

`--format figma-description` reads UTF-8 text containing explicit blocks:

```text
[dsg-rule id=button-primary.max-per-widget class=machine]
max_instances_per_scope: identity=Button/Primary scope=widget_class max=1
[/dsg-rule]
```

The caller also supplies exact host kind, host identity, Figma file key, node
ID, and source version. Text outside explicit markers is reported as ignored
context and is never converted into a rule.

An optional UTF-8 JSON array passed through `--known-identities` lets the preview
report identify unresolved rule targets. This list is untrusted preview input;
it can never approve an identity or contribute to a production pass.

## Validation report

`schemas/rules-validation-report.schema.json` defines the deterministic CLI
projection. It contains only rule IDs, classes, tiers, exact reason codes,
counts, a digest of valid normalized rules, and these fixed safety fields:

- `authority: preview_only`
- `localChangesPerformed: false`
- `productionReady: false`

It contains no source text, statement text, raw excerpt, absolute path, company
name, prompt, credential, or user activity.

Result mapping:

- structurally and referentially valid preview: exit `0`
- invalid or ambiguous rule input: exit `2`
- structurally valid but identity coverage not supplied: exit `4`

No v0.3.4 result can be consumed by audit or finalization.

## Internal architecture

- `guardian_core/rules.py`: strict parser, normalizer, validator, canonical
  ordering, digest, safe input-size limits, and preview report assembly.
- `guardian_core/cli.py`: additive `rules validate` command only.
- `schemas/rule.schema.json`: portable rule contract.
- `schemas/rules-validation-report.schema.json`: portable preview-report
  contract.

The module uses existing canonical JSON and hashing helpers. Content problems
become report entries. Invalid containers, duplicate JSON keys, unsafe sizes,
and malformed CLI contracts fail closed.

## Compatibility and rollback

v0.3.4 performs no migration and writes no Guardian state. Existing profiles,
snapshots, audit history, run pins, Elo history, and trust anchors remain
byte-identical. Rolling back means reinstalling v0.3.3; no data downgrade or
cleanup is required.

## Implementation plan

1. Add failing schema tests for both strict contracts and update the exact CI
   schema inventory from 23 to 25.
2. Add failing parser and validator tests covering every rule class, every
   predicate shape, marker smuggling, unknown fields, duplicate IDs, unknown
   identities, deterministic ordering, input limits, and non-disclosure.
3. Add failing CLI tests for both input formats and exact exit mappings; prove
   the command performs no writes.
4. Implement `guardian_core/rules.py` using only existing standard-library and
   canonical helpers.
5. Add the `rules validate` parser and handler without touching existing
   commands or state.
6. Extend public-release privacy tests and synthetic pressure cases without
   storing real rule content.
7. Add an immutable Elo v4 benchmark module and record only independently
   verified public synthetic achievements.
8. Update v0.3.4 manifests, documentation, changelog, and packaging assertions.
9. Run focused tests, the complete 403-test baseline plus new tests, all Flutter
   tests, schema validation, plugin/skill validators, Figma collector syntax,
   privacy/history gates, deterministic plugin audit, and diff/secret checks.
10. Commit, push, merge after CI, publish v0.3.4, reinstall, and verify with
    fresh agents. Stop rather than publish if any required gate is incomplete.

## Acceptance criteria

- Reordering equivalent candidates within one source form produces the same
  normalized rules and digest.
- Unknown syntax, properties, predicates, duplicate IDs, and ambiguous values
  fail closed with exact non-sensitive diagnostics.
- Ordinary Figma prose is never interpreted as a rule.
- Missing identity coverage is `not_assessed`, never a pass.
- The command never writes local Guardian or project state.
- Existing v0.3.3 tests and artifacts remain unchanged and readable.
- The immutable policy digest and exactly two visible skills remain unchanged.
- Public history contains no real company rule, identifier, source text, path,
  prompt, credential, or runtime report.
